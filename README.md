I’m starting a series of Monte Carlo simulations to explore how random outcomes can help us understand probability, uncertainty and risk. I’ll begin with a simple dice experiment to learn the underlying method, then gradually work towards more complex applications involving financial markets and investment risk.

Monte Carlo simulation involves repeating an experiment many times using randomly generated values and analysing the results. Instead of calculating every possible outcome directly, we simulate a large number of possible outcomes to estimate quantities such as probabilities or average values. This is particularly useful when a problem has many uncertain inputs or is too complicated to solve easily using an exact formula.

My first simulation looks at a straightforward question: what is the probability that two fair six-sided dice add up to exactly seven? The Python code randomly generates a value between one and six for each die, adds the values together and checks whether the total equals seven. It repeats this process 10,000 times and counts the number of successful trials. Dividing that count by the total number of trials gives an estimate of the probability.

This example gives me a clear way to check whether the simulation is working because the exact answer is already known. There are 36 equally likely combinations when rolling two independent fair dice, and six of them add up to seven. The theoretical probability is therefore \(1/6\), or approximately 16.67%. Comparing the simulated result with this value helps demonstrate both the usefulness of the method and the variation that comes from random sampling.

Each run will produce a slightly different estimate. Increasing the number of trials generally makes the estimate more precise, although it does not guarantee that every larger simulation will be closer to the exact answer. I also want to explore how the results change as I increase the number of trials and how we can describe the uncertainty around an estimate.

As I become more comfortable with the method, I plan to apply it to financial markets and investment risk. Rather than simulating dice rolls, these models could simulate possible investment returns over time. Repeating the process across many possible paths would allow me to examine a range of potential portfolio values, estimate the probability of a loss and investigate how different assumptions affect the results.

I’m particularly interested in looking beyond a single average return. Two investments could have similar average outcomes but very different levels of uncertainty. A simulation can help illustrate that difference by showing how widely outcomes vary and how often particularly poor results occur. It could also provide a way to explore how investment horizons, regular contributions and diversification influence the range of possible outcomes.

An important part of this project will be understanding the assumptions behind each model. Dice have known probabilities, while financial returns are much harder to describe. Market simulations depend on choices about expected returns, volatility and how assets move together. Running more simulations can reduce random sampling error, but it cannot correct unrealistic assumptions or make an uncertain market predictable.

Through this series, I want to build my Python skills while developing a more practical understanding of statistics. Starting with dice gives me a foundation I can explain and verify. Moving towards markets and investing will allow me to explore how the same basic method can support more complex questions, while learning how to interpret the results and recognise their limitations.
